# Governance and operating model

Digital services need named owners after launch. The service owner remains accountable for the
end-to-end resident experience, while technology, privacy, security, accessibility, procurement,
and operations provide defined controls and evidence.

## RACI summary

| Activity | Service owner | Product lead | IT and architecture | Security | DPO | Accessibility lead | Supplier |
|---|---|---|---|---|---|---|---|
| Define outcome and service standard | A | R | C | C | C | C | I |
| Map data and lawful basis | C | R | C | C | A | I | I |
| Approve architecture and integrations | C | C | A/R | C | C | I | C |
| Validate security controls | I | C | C | A/R | C | I | R |
| Validate accessibility | C | R | C | I | I | A | R |
| Accept release | A | R | R | C | C | C | C |
| Operate and support | A | C | R | C | C | C | R |
| Review benefits and risks | A | R | C | C | C | C | I |

## Governance gates

1. **Discovery gate:** verified user need, baseline metrics, legal owner, and service owner.
2. **Design gate:** architecture decision record, data inventory, threat model, accessibility plan,
   supplier responsibilities, and measurable acceptance criteria.
3. **Pilot gate:** tested recovery, incident contacts, staff training, assisted channel, and rollback.
4. **Scale gate:** adoption evidence, control effectiveness, support capacity, and funded ownership.

Procurement should require open interfaces, exportable data, operational documentation, audit
rights, service levels, vulnerability handling, and an executable exit plan.
